# 扫码绑定表格数据（qr-bind-table-data）

## ADDED Requirements

### Requirement: 逐个扫码绑定表格行

上传检测数据 Excel（或载入历史批次）后，用户逐个扫描实物二维码并在记录表格中点选对应行，确认后建立「码值 ↔ 记录」绑定。

#### Scenario: 扫码并选行绑定

- **WHEN** 用户在绑定页上传 Excel（或载入历史批次）后摄像头扫码（或手动输入码值）
- **AND** 在记录表格中点选一行并点击「确认绑定」
- **THEN** 绑定关系写入本机 `code-bindings` 仓库（含码值、来源批次、记录快照、绑定时间）
- **AND** 该行标记为已绑定并展示绑定码值，待绑定码清空，可继续扫下一个

#### Scenario: 外部码原样绑定

- **WHEN** 扫描的码值不满足任何已知内容模式（外部供应商码等）
- **THEN** 码值原样存储（不解析、不校验格式），绑定与查询行为与规则码一致

#### Scenario: 一码一行重绑覆盖

- **WHEN** 确认绑定的码值已绑定其他记录行（或所选行已绑定其他码值）
- **THEN** 界面先提示已绑定的旧关系，用户确认后覆盖旧绑定（同一码只指向一条记录、一条记录只挂一个码）

#### Scenario: 解绑

- **WHEN** 用户在已绑定行或绑定记录列表上执行解绑/删除
- **THEN** 该绑定从本机删除，行绑定标记与列表同步刷新；来源批次数据不受影响

### Requirement: 绑定关系独立于批次留存

绑定存记录快照（序号/时间/判定/测量值）而非对批次的引用。

#### Scenario: 来源批次删除后绑定仍可查

- **WHEN** 绑定建立后其来源批次被删除
- **THEN** 溯源查询页扫描该码仍能展示绑定的记录数据（快照自包含）

## MODIFIED Requirements

### Requirement: 溯源查询优先检索绑定库

**FROM**: 输入或扫码获取码值后，按明文文本/编码规则两种模式解析展示溯源信息；编码规则码按码回查本地批次关联记录。

**TO**: 输入或扫码获取码值后，先检索本机绑定库（任何码值都可能已绑定，含外部码与规则码），命中直接展示绑定的记录（序号/时间/判定/测量值/来源批次/绑定时间）；未绑定再按明文文本/编码规则两种模式解析展示，编码规则码按码回查本地批次关联记录。

#### Scenario: 扫描已绑定的外部码

- **WHEN** 查询页扫描一个已建立绑定的外部码（不满足任何解析模式）
- **THEN** 直接展示该码绑定的检测记录与来源批次信息，不报「无法识别」

#### Scenario: 扫描未绑定的码

- **WHEN** 查询页扫描一个未建立绑定的码值
- **THEN** 回退现有模式解析流程（明文/规则码拆段/规则码关联回查），行为与改动前一致
