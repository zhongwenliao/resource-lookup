# 提案：二维码生成（生成端能力规格化）

## Why

标签生成页（`QcLabel.vue`）已具备完整能力，但行为没有规格约束：编码规则模式近期调整为「试制阶段/颜色直接输入（填名称自动转码）」与「年份/月份自动取当前或手动输入」，这些行为仅存在于代码与注释中；同时编码规则常量与拼码逻辑内聚在组件里，与进行中的溯源查询变更（`qr-traceability-lookup`）各自维护一套规则，存在两端规则漂移风险。需要把生成端行为固化为规格，并抽取共享规则模块作为生成/查询两端唯一事实来源。此外，导入的表格数据目前仅存于组件内存，页面刷新或关闭即丢失、无法回溯历史批次，需要将导入数据落入前端数据库本地持久化。产品决策：二维码内容只保留编码规则模式（明文文本与网页链接模式移除）；且编码规则码仅含拼码配置信息、不含记录明细，扫码后要回查对应检测记录，必须在生成时建立规则码与记录的关联并持久化。

## What Changes

- 新增能力规格 `qr-code-generation`，固化标签生成页七块行为：
  - Excel 导入与列自动识别（判定/序号/时间/测量列，判定列可手动改选）
  - 导入数据本地持久化：解析成功的批次自动写入前端数据库（IndexedDB），支持历史批次查看/载入/删除
  - 规则码与记录关联持久化：批量生成时把每条 OK 记录的规则码写入批次记录明细，供查询端按码回查对应检测记录
  - 二维码内容收窄为编码规则单一模式（KBWK@@##*!%YMMDDXXXXX），移除明文文本与网页链接模式入口
  - 编码规则模式配置：项目/组件/阶段/颜色直接输入（阶段名、颜色名自动转码），年份/月份「自动取当前 / 手动输入」切换，日期取记录检测时间或手动指定，五位流水码逐条递增
  - 批量生成（分批进度、失败中止、预览）
  - 标签打印排版（标签纸 / A4 裁切 / 小票纸连续纸，可另存 PDF）
  - BarTender BTXML 打印与导出（与浏览器打印同码值）
- 重构：把编码规则常量与纯函数（`STAGE_CODE_MAP`/`COLOR_CODE_MAP`/`MONTH_CODES`/`normalizeStage`/`normalizeColor`/`pad2`/`pad5`）从 `QcLabel.vue` 抽取到 `src/common/qc-code-rules.js`，供生成端与查询端共用
- 行为边界：模块抽取为零行为变化重构，阶段/颜色直接输入、年份/月份自动/手动等近期调整一并纳入规格；新增行为为「导入数据本地持久化」「规则码与记录关联持久化」，以及「内容模式收窄为编码规则」（移除明文/网页链接入口）

## Capabilities

### New Capabilities

- `qr-code-generation`: 质检二维码标签生成——检测 Excel 导入解析与本地持久化（含规则码与记录关联）、编码规则单一码值模式、批量生成二维码、标签排版打印与 BarTender BTXML 输出

### Modified Capabilities

（无——`qr-traceability-lookup` 尚未实施归档；其任务 1.1/1.2 计划的共享规则模块抽取由本变更承接，apply 时需同步改写该变更任务清单中对 `STAGE_OPTIONS`/`COLOR_OPTIONS` 的过时引用）

## Impact

- `src/views/QcLabel.vue`：常量与纯函数迁出，改为引用 `src/common/qc-code-rules.js`；新增历史批次查看/载入/删除界面；移除明文文本与网页链接模式的切换入口与码值组装分支
- 新增 `src/common/qc-code-rules.js`：编码规则常量、名称→码值归一化、base64url 编解码、规则码拆段校验
- 新增 `src/common/qc-db.js`：IndexedDB 轻封装，导入批次本地持久化（仅存源记录与统计，不存二维码图片），并提供按规则码检索关联记录的接口
- 与 `qr-traceability-lookup` 变更协同：共享模块是查询端解析逻辑的前置依赖，两个变更的任务清单需对齐，避免重复抽取
- 无新增依赖（IndexedDB 为浏览器与 Electron 渲染进程原生能力）；全程纯前端处理，检测数据不出本机、不上传任何服务端
